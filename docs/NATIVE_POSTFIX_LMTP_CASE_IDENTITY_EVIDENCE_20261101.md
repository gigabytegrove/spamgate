# Exact-message Postfix/Milter/Dovecot LMTP evidence — 2026-11-01

The disposable Ubuntu 24.04 Postfix/Dovecot integration previously established
the correct **aggregate** change of four INBOX and one Junk message. Aggregate
counts alone cannot distinguish a missing expected message from an unexpected
replacement, a misrouted case, or a rejected message delivered accidentally.

## New independent evidence gate

`scripts/spamgate-lmtp-case-evidence.py` records a read-only Dovecot
`doveadm search` UID inventory for each of seven actual SMTP fixtures, in
both INBOX and Junk. The query is bound to the exact Message-ID from the Go
Postfix integration test. Before and after inventories are compared:

| Message-ID local part | Expected new INBOX | Expected new Junk |
| --- | ---: | ---: |
| legitimate | 1 | 0 |
| null-reverse-path | 1 | 0 |
| hold-request | 1 | 0 |
| tag-to-junk | 0 | 1 |
| forged-verdict | 1 | 0 |
| synthetic-reject | 0 | 0 |
| storage-failure | 0 | 0 |

The forged-verdict fixture now supplies a stable Message-ID. Previous LDA-phase
copies have identical Message-IDs; this is intentional. The evidence compares
Dovecot UID fingerprints rather than assuming the before inventory is empty.
The exact five newly delivered identities must be unique and previously
observed identities must remain present.

The existing independent aggregate mailbox delta gate remains in place.
**Both gates must pass.** Together they reject unexplained aggregate additions,
missing individual deliveries, wrong INBOX/Junk disposition, duplicate case
identities, and delivery after SMTP reject or temporary failure.

## Safety and privacy

Active mail submission remains confined to the existing Go integration test.
The new Python collector never submits mail, changes Postfix/Dovecot, reads
message bodies, or exposes mailbox addresses in its output. It requires
`CI=true`, `GITHUB_ACTIONS=true`,
`SPAMGATE_DISPOSABLE_POSTFIX_LMTP_LAB=1`, and the exact
`--confirm DISPOSABLE-POSTFIX-LMTP-QUALIFICATION` opt-in.

Dovecot queries have bounded execution and output. Evidence JSON is bounded,
rejects symlinks and non-regular files using `O_NOFOLLOW` and `fstat`,
and refuses duplicate JSON keys, non-finite constants, malformed UID
fingerprints and ambiguous schemas.

The new hermetic regression suite is run by
`.github/workflows/engineering-qualification.yml`; actual Postfix-to-LMTP
evidence is generated by `.github/workflows/postfix-dovecot-lab.yml`.
The resulting JSON files are retained with the exact-commit lab artifact.

## Unqualified scope

These are disposable-host tests, **not** real production mail-host
qualification. This work does not establish ISPConfig persistence,
multi-recipient ownership, independent authentication interoperability,
crash-injected at-least-once delivery, real-world classifier precision,
tenant policy completeness, browser acceptance, or native disaster recovery.
All nine cumulative production gates remain open. The October 31 beta
deadline has passed and SpamGate must not be declared beta-qualified.
