# Live mail activity and scoring in SpamGate 0.4.0-alpha.8

The Web UI now checks for new stored scan records every four seconds while the tab is visible and the user is authenticated. It queries only the most recent record first; when a new ID is observed, it retrieves the latest 1,000 messages and overall retained-history statistics. Polling neither opens mail nor changes verdicts. Form fields and open message reviews are never replaced mid-edit; use **Refresh now** to catch up if you were reading a message or editing a form when mail arrived. Connectivity errors display a warning without declaring that mail filtering stopped.

Home lists recently scanned messages including accepted mail, a queue of flagged messages, and frequently triggered scoring signals from the locally loaded records. These counts are distinct from delivery receipts. When connected via Postfix Milter, SpamGate records the verdict returned to Postfix; Postfix remains responsible for reporting final delivery.

Every newly scanned message stores its **scoring trace**, containing tag, quarantine and reject thresholds as configured **at scan time**; the resulting forced action when a matching rule overrode the score; and named scan check statuses such as match, no match, pass, fail, disabled/not configured, informational or error. The same message also retains all original finding symbols, provenance, weights and explanations. Score totals are the sum of the findings. The score trace is additive to the stored message schema: old scans remain readable, with an explicit legacy-data note instead of fabricated historic thresholds. Actual raw email originals are not stored with a Milter scan by default.

**Limits:** An enabled detection algorithm does not establish that a message was safe; built-in URL detection is heuristic, ARC verification remains structural, and ClamAV scanning is only performed if a clamd address is configured. DNSBL failures are not fully itemized per DNS query. Neural/Bayes require explicit training. Signatures and mail policy checks remain partial compared to mature Rspamd. Scan trace statuses are an audit of the code path, not a comprehensive assurance report.

**Standalone testing:** The binaries in the standalone ZIP run from the extracted directory without installer, service registration or Postfix modifications. Keep using the existing data directory to preserve message history. Port 38470 Web UI and 38472 loopback Milter bindings remain selectable exactly as in alpha.7. Rebuilding from source with a supported Go release is required before security-sensitive deployment: alpha.8 development binaries were compiled with Go 1.23.2.
